# Lessons

- Before marking a repository task complete, verify open PR count, pending/failed required checks, and open security alerts. Background completion is not task completion.
- GitHub may redact a numeric timestamp job output when secret scanning classifies it as sensitive. For cross-job control state, use an artifact and verify the downstream job receives the value during a live run; artifact upload alone is insufficient proof.
- GitHub workflow disable is not idempotent and disabled workflows may not resolve by display name in `gh run list`. Read current state before disabling and use stable workflow filenames/IDs for lifecycle cleanup.
- A cleanup claim must state its scope. Before calling workflow history clean, count runs repository-wide and verify every workflow covered by the stated retention policy—not only the workflow that owns the cleanup job.
- Before relying on a dependency's convenience method, inspect its installed implementation and production logs for undeclared optional runtime requirements. nodriver 0.50.3 `verify_cf()` calls OpenCV-based `template_location()`; without hash-locked `opencv-python-headless`, no checkbox coordinates or click are produced.
- Runner-local Chrome startup failure (nodriver `Failed to connect to browser`) is not fixed by in-process retries on the same runner; only a fresh workflow run on a new runner recovers. Signal this with a credential-free marker artifact, not in the Telegram report text, so downstream dispatch can be automated without exposing credentials.
- CAPTCHA/Turnstile policy must be phase-independent: if a challenge appears after clicking Vote or after verification reload, call nodriver `verify_cf()` via the shared solver before reporting captcha_required. Terminal CAPTCHA reporting is only after solver failure, not on first detection.
- Before clicking Turnstile or vote controls, clear site-level consent/privacy overlays. Visual blockers can cover the target while DOM detection still says the target exists, causing verify/click flakiness.
- For random modal blockers, guard the lowest click primitive as well as page-level flow. Call overlay dismissal immediately before the actual click, because a modal can appear between earlier checks and the click.
- When an automatic blocker-dismiss step fails while a blocker is present, report the failure at the user boundary with a screenshot and redacted reason, then dedupe to avoid Telegram spam.
- Quantcast consent modals can place visible text inside child spans, so privacy-dismiss detection must prefer stable selectors like #accept-btn and include textContent/id fallback, not only innerText.
- Privacy/consent modals may appear after navigation completes and after an initial sleep; use a short settle loop after page open/reload before checking auth or clicking Login.
- Final top.gg auth_failed after all retries needs browser-state evidence, not only text report. Capture on the last retry only and send after the report to avoid retry spam.
- A repository secret whose value is a single character (for example `1`) makes GitHub redact every matching substring in run logs and job outputs. A numeric job output then looks like a secret, gets dropped, and downstream gates fail permanently. Publish non-numeric status tokens (`ok`/`fail`) and keep short secrets as words, never single characters.
- Browser cleanup failures must never replace the original error in `start_browser`. A raised `BrowserCleanupError` during startup cleanup hides `BrowserStartupError`, which suppresses the browser-startup fresh-runner retry marker and leaves the feature silently disabled.
- An edge challenge blocks the session API too, so a non-OK `/api/auth/session` response is not proof of an invalid session. Classify the response (status plus content type) before deciding the cookie is expired, and report a challenge as its own terminal status instead of retrying it from the same IP.
- Cloudflare clearance cookies must survive the cookie export filter. A browser that already passed the challenge still gets challenged on every run if `cf_clearance` is dropped during export.
- A proxy must be attached to the browser context, not only to the launch flags. The default tab belongs to the initial context and would bypass the proxy, so the automation tab must be created through `browser.create_context(proxy_server=...)`.
- Free public proxy lists are not a substitute for residential egress. Measured 2026-10-21 across 2,965 listed proxies: 8.9% were functionally alive and 0% reached top.gg without still being served the Cloudflare challenge.
- A Cloudflare WARP egress is not challenged by top.gg the way datacenter ranges are. Use the official `warp-cli` in proxy mode, not raw WireGuard: hosted runners and Oracle Cloud both drop WireGuard UDP (2408, 500, 1701, 4500) while the official client connects over an unfiltered transport.
- A same-origin `fetch` is challenged while a document navigation to the same path succeeds, and the difference is the `Accept` header. `Accept: */*` on the XHR gets HTTP 403 with `cf-mitigated: challenge`; sending `Accept: application/json, text/plain, */*` returns the real JSON payload. The session probe must send the JSON Accept header.
- The consent overlay must be fully dismissed and allowed to settle before the session probe runs. While the overlay is up, the XHR is answered with a challenge document instead of JSON.
- Measuring a JavaScript challenge with `curl` is invalid: curl never runs the challenge script, so a proxy that a real browser passes looks dead. Always re-test a proxy in an actual browser before rejecting it.
